# traffic_survey-facial-identification-raspi3

Raspberry Pi 3 上で動作する、**顔検出による通行量計測システム**です。カメラ映像から顔をリアルタイムに検出・追跡して延べ通行量をカウントし、計測終了後に局所特徴量マッチングで同一人物の重複を除去することで「実際に何人が通行したか」を算出します。

---

## 開発の背景・目的

> 本セクションは制作当時の経緯をもとにした記述です。

学校の授業課題・演習の成果物として制作しました。

歩行者の通行量調査は、現在も調査員が手押しカウンターで数える人海戦術が主流であり、長時間の計測ではコストと計測精度の両立が難しいという課題があります。これをカメラと画像処理で自動化できないか、というのが出発点でした。

しかし単純に「顔を検出した回数」を数えるだけでは、以下の理由で正しい通行量になりません。

1. 同一人物が複数フレームに写るため、フレームごとに検出すると同じ人を何度も数えてしまう
2. 一度フレームアウトした人物が再び戻ってきた場合、別人として二重にカウントされてしまう

そこで本プロジェクトでは、**「リアルタイム処理で延べ人数を数える」段階と、「計測終了後に顔画像を照合して重複を除く」段階を分離した2段構成**を採用しました。処理能力の限られた Raspberry Pi 3 という制約下で、リアルタイム性と識別精度をどう両立させるかが最大のテーマです。

## 処理フロー

```
[カメラ入力 640x480]
        |
        v
[グレースケール化 + ヒストグラム平坦化]
        |
        v
[Haar-like カスケード分類器で顔検出]
        |
        +--> 既存の追跡窓と重心が対応する --> 追跡窓・色ヒストグラムを更新
        |                                     顔画像を追加保存（1人あたり最大10枚）
        |
        +--> 対応する追跡窓がない ----------> 新規 ID を採番し延べ人数 +1
                                              顔画像を保存
        |
        v
[MeanShift で全追跡対象を追跡 / 重複窓・画面外の窓を破棄]
        |
        v
  ( q キーまたは映像終了 )
        |
        v
[後処理: identification.sosu()]
        |
        +--> 人物ごとに AGAST の特徴点数が最大のフレームを代表画像として選出
        +--> 全代表画像を SIFT / SURF で総当たりマッチング
        +--> 同一人物と判定されたペアを統合し、重複を除いた実人数を算出
```

---

## 主な機能・実装したこと

- **リアルタイム顔検出** — Haar-like 特徴カスケード分類器による正面顔検出。前処理としてグレースケール化とヒストグラム平坦化を行い、照明条件の変動に対する頑健性を確保
- **最大10人の同時追跡** — HSV 色相ヒストグラムのバックプロジェクションを用いた MeanShift による追跡。追跡対象ごとに ID（`N_HUMAN`）を採番して画面上に描画
- **延べ通行量のカウント** — 検出矩形と既存追跡窓の対応付けにより、同一人物の重複計上を回避しながら通行人数を加算。累計人数を画面にオーバーレイ表示
- **顔画像の自動収集** — 検出した顔領域を `face/faceN_M.jpg` として人物ごとに最大10枚保存し、後処理の入力とする
- **代表フレームの自動選出** — 保存した複数フレームのうち AGAST 検出器の特徴点数が最大のものを、その人物の代表画像として自動選択
- **特徴量マッチングによる同一人物判定** — SIFT と SURF の2つの記述子で全代表画像を総当たり照合し、重複を除いた実人数を算出
- **結果の出力** — 延べ人数を `face/total_people.txt` に、特徴点を重畳した可視化画像を `face_key/keypointsN.jpg` に書き出し

## こだわったポイント・工夫した点

### 1. 計算コストに応じた2段構えのアーキテクチャ

SIFT / SURF による特徴量マッチングは全人物の総当たり比較となるため、Raspberry Pi 3 でリアルタイムに実行することは現実的ではありません。そこで**リアルタイム処理には軽量な Haar 検出と MeanShift 追跡のみを使い、計算量の大きい特徴量マッチングは計測終了後の後処理に完全に分離**しました。リアルタイム側は「延べ人数のカウントと顔画像の収集」に責務を絞り、精度を要求する識別処理は時間制約のない後処理側に寄せるという設計です。

### 2. 検出と追跡の併用による重複カウントの抑制

顔検出だけでは同一人物を毎フレーム数えてしまいます。そこで検出矩形の重心が既存の追跡窓の近傍（マージン 30px）に入るかどうかで同一人物か新規人物かを判定し、既存人物であればカウントせず追跡窓と色ヒストグラムのみを更新する方式にしました。

### 3. 誤検出・誤カウントを減らすための境界条件

- **画面端の除外** — 検出矩形が画面端 10px 以内にかかる場合は新規カウントの対象外とし、見切れた顔による誤カウントを防止
- **重複追跡窓の統合** — ある追跡窓の重心が別の追跡窓の内側に入った場合、一方を破棄して同一人物の二重追跡を解消
- **画面外に出た追跡窓の破棄** — 追跡窓が画面境界を越えた時点で追跡を打ち切り、ゴースト追跡を防止

### 4. 照合精度を高めるための代表画像選出

同一人物の顔画像でも、モーションブラーや顔の向きによって照合に使える特徴点の数は大きく変動します。そこで**1人につき最大10フレームを蓄積し、AGAST 検出器で検出される特徴点数が最大のフレームを代表画像として自動選出**する仕組みを入れました。品質の低いフレーム同士を比較して誤判定するリスクを構造的に減らしています。

### 5. 2種類の記述子による AND 条件判定

単一の特徴量記述子では他人を同一人物と誤判定するケースがあったため、**SIFT と SURF の両方で類似度を計算し、双方が閾値を下回った場合のみ同一人物と判定**する AND 条件を採用しました。類似度の指標には、マッチング距離の上位4件の平均値を使用しています。

### 6. 特徴量記述子の比較検討

`identification.py` の冒頭には、BRISK / ORB / LATCH / BRIEF / DAISY / FREAK / MSER / AKAZE / KAZE といった各種特徴量抽出器の生成コードが残っています。これは最終的に SIFT + SURF の組み合わせに落ち着くまでに、複数の記述子を実際に差し替えて精度を比較検証した過程によるものです。検出器・記述子・マッチャーを引数で受け取る `calc()` 関数として共通化することで、記述子の差し替えを容易にしています。

## ローカルでの環境構築・起動手順

### 1. 前提環境

- Raspberry Pi 3（Raspbian）または OpenCV が動作する Linux 環境
- Python 2.7
- `opencv_contrib` を含み、non-free モジュール（SIFT / SURF）を有効にしてビルドした OpenCV 3.x
- NumPy
- USB Web カメラ（`/dev/video0`）または Raspberry Pi カメラモジュール

```bash
pip install numpy
```

OpenCV は `xfeatures2d` を利用するため、パッケージマネージャの標準版ではなく `opencv_contrib` 付きでのソースビルドが必要です。

### 2. リポジトリの取得と出力先ディレクトリの作成

顔画像と特徴点可視化画像の出力先は事前に作成しておく必要があります。

```bash
git clone https://github.com/TMNTmaker/traffic_survey-facial-identification-raspi3.git
cd traffic_survey-facial-identification-raspi3
mkdir face face_key
```

### 3. 実行

```bash
python traffic_survey.py
```

カスケードファイルを差し替える場合はオプションで指定できます。

```bash
python traffic_survey.py --cascade haarcascade_frontalface_alt.xml
```

### 4. 操作方法

- ウィンドウに検出矩形・追跡矩形・人物 ID・累計通行人数がリアルタイム表示されます
- **`q` キー**を押すと計測を終了し、続けて後処理（同一人物判定）が実行されます
- コンソールに各ペアの照合結果と、重複を除いた実人数が出力されます

### 5. 出力ファイル

| パス | 内容 |
| --- | --- |
| `face/faceN_M.jpg` | 人物 N の M 枚目の顔画像 |
| `face/faceN.jpg` | 人物 N の代表画像（後処理で選出） |
| `face_key/keypointsN.jpg` | 人物 N の代表画像に特徴点を重畳した可視化画像 |
| `face/total_people.txt` | 延べ通行人数 |

### 6. 動画ファイルを入力にする場合

カメラの代わりに録画済みの動画で検証する場合は、`traffic_survey.py` の以下の箇所のコメントを入れ替えます。

```python
#cap = cv2.VideoCapture('Output2.avi')  # 動画ファイルをキャプチャする場合
cap = cv2.VideoCapture(0)               # webカメラを使用する場合
```

## 既知の課題・今後の改善点

本リポジトリは制作当時（2016年）のコードをそのまま保存しています。現在の視点で振り返ると、以下の課題があります。

**動作上の不具合**

- `traffic_survey.py` の終了処理が、モジュール名の変更に追従できておらず未定義の `test.sosu()` を呼び出している（正しくは `identification.sosu()`）
- `identification.py` にタブとスペースが混在した箇所があり、インデントが不整合になっている
- `identification.py` の可視化処理で未定義変数 `k4` を参照している（`k2` / `k3` の誤り）

**設計・保守性の課題**

- `xrange` など Python 2 固有の記法に依存しており、Python 3 では動作しない
- 追跡対象の上限（10人）、判定マージン（30px）、照合閾値（SIFT: 200 / SURF: 0.20）などがマジックナンバーとしてハードコードされており、設定ファイルや引数として外出しすべき
- 出力先が `face/` `face_key/` に決め打ちされ、ディレクトリの自動作成も行っていない
- グローバル変数への依存度が高く、検出・追跡・カウントの責務が `while` ループ内に混在している。クラスとして分離すべき箇所

**アルゴリズム面の改善余地**

- 正面顔のみを対象としているため、横顔や俯いた歩行者を取りこぼす
- 現在であれば、顔検出は CNN ベースの検出器（MTCNN・RetinaFace 等）、同一人物判定は深層距離学習による顔認識（FaceNet・ArcFace 等）、追跡は SORT / DeepSORT といった手法を用いることで、精度・頑健性ともに大きく改善できる
